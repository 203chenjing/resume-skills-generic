# 简历数据库

> **层级说明**：L0 原始证据 → L1 结构化 STAR（批量召回原子单位）→ L2 投递策略（archetype 金样与映射）。  
> 写法细则见 `reference.md`；本文件为 **L0/L1/L2 空白模板**。

---

## 知识库层级索引

| 层级 | 区块 | 用途 | 是否写入投递简历 |
|------|------|------|------------------|
| **L0** | `## L0 原始证据层` | 只增不改的原始材料与线索 | 否 |
| **L1** | `## L1 结构化 STAR 层` | 每条 STAR = story_bank 一条召回单元 | 否（抽取后改写） |
| **L2** | `## L2 投递策略层` | archetype 金样、压缩规则、JD 映射 | 否 |

**维护原则**

- L0 → 用户确认后升格为 L1；L1 经 JD 验证后更新 L2 映射笔记。
- 每条 L1 STAR 必须有 `story-id`、来源证据、可选 `#tags` 与 `fit_archetypes`。
- 缺指标写 `[待补充：指标]`；无来源数字不得标 `resume-ready: yes`。

## 附录：story-meta 行规范（供 story_bank 解析）

每条 L1 STAR 标题下用 **一行 blockquote** 写元数据（必填 `story-id` + `level: L1`）：

```markdown
#### STAR 1：识别业务流程痛点

> story-id: `{employer-slug}-01` · level: L1 · priority: P0 · archetypes: {岗位类型A}, {岗位类型B} · tags: #关键词1 #关键词2 · evidence: ev-01 · resume-ready: yes
```

| 字段 | 说明 |
|------|------|
| `story-id` | 全局唯一，建议 `{雇主slug}-{序号}` |
| `level` | 固定 `L1`（L0 线索不单独召回） |
| `priority` | P0 主亮点 / P1 补充 / P2 选配 |
| `archetypes` | 逗号分隔，供 JD archetype 加权 |
| `tags` | `#tag` 与 archetypes 共同参与召回 |
| `evidence` | 对应 L0 `evidence-id`，多个用逗号 |
| `resume-ready` | `yes` 表示指标已确认，可进投递草稿 |
