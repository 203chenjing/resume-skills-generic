# 简历知识库 — 结构与写法参考

## L0 / L1 / L2 三层模型（2026-06）

| 层级 | Markdown 区块 | 职责 | story_bank |
|------|---------------|------|------------|
| **L0 原始证据** | `## L0 …` / `## 原始简历提取内容` | 只搬运原始事实与 evidence-id | 不召回 |
| **L1 结构化 STAR** | 雇主 `##` 下 `#### STAR …` + story-meta 行 | 批量改简历的原子 bullet 库 | **召回单元** |
| **L2 投递策略** | `## L2 …` / JD 映射 / archetype 金样 | 压缩规则、优先 story-id、关键词索引 | 映射重排（可选） |

空白模板见 [`resume-database-l012-template.md`](resume-database-l012-template.md)。

### story-meta 行（L1 必填约定）

```markdown
#### STAR 2：标题

> story-id: `story-01` · level: L1 · priority: P0 · archetypes: {岗位类型A}, {岗位类型B} · tags: #关键词1 #关键词2 · evidence: ev-01 · resume-ready: yes
```

## 各区块职责

### 原始简历提取内容

- **只搬运、不润色**：联系方式、教育、技能、实习/工作、项目名、职责短语、已有数字
- 标注来源：`来源：{文件名}`
- 保留原始表述，便于按不同 JD 改写

### 经历与项目线索（原始层）

- 按雇主：`**{公司}｜{岗位}**` + 日期
- 其下 `- **{工作线名}**：` 并列列出，每条一段原始描述
- 同一雇主的多条工作线**并列**，除非原始材料明确父子关系

### 扩展项目块（STAR 层）

- 信息量大、常跨多类 JD 的项目可单独开节
- 每节：`背景/痛点 → 任务 → 动作 → 工具/协同 → 结果/指标`
- **动作应尽量细**：写清步骤、产物（PRD/流程图/Schema）、字段口径、编排节点、协同方，便于从 Action 反推完整工作内容；投递简历再压缩
- 可选附 `工作内容反推` 表（从动作映射到调研/PRD/工作流/跨团队等）
- 可选附 `可直接改写到简历的版本`（1–5 条草稿 bullet），须基于已确认事实

### 使用规则（按需）

写在知识库内部，**不**写入投递简历。典型条目：

| 规则类型 | 内容 |
|----------|------|
| 项目归属 | 属于哪段实习/工作，是否独立成段实习 |
| 并列关系 | 哪些工作线并列，不得写成「总项目统摄子项目」 |
| JD 压缩策略 | 强相关岗位写哪些线、非相关岗位合并为几条 |
| 正式简历标题 | 公司+岗位+时间；项目名放 bullet 标题或正文 |

### 可复用关键词

按类归纳，供 JD 匹配检索，不必写入投递简历：

- 岗位方向、业务场景、通用能力、工具/方法、量化证据

### 指标清单

```text
| 指标 | 来源 | 上下文 | 能否写入简历 |
| {描述} | {原始简历/复盘/口述} | {工作线或项目} | yes/no/待确认 |
```

无来源的数字不得标 `yes`。

### 待确认事实

集中存放 `[待确认]` 的日期、职级、指标、敏感表述；确认后迁入正式块或指标清单。

### JD 映射笔记（可选）

按岗位类型记录：优先写哪些经历、压缩哪些经历、常用关键词。仅服务 tailoring，不进投递简历。

## Workflow 细则

**1. 检查已有库** — 通读 `简历数据库.md`，与用户确认本次新增/修订范围。

**2. 导入原始事实** — 提取基本信息、教育、技能、经历、荣誉、日期；乱码或缺失向用户确认；不确定写 `[待确认]`。

**3. 整理雇主与并列项目** — 一段实习/工作 = 一个雇主块；工作线并列；需规则时写 `### 使用规则`。

**4. 补全 STAR** — 每条主要工作线含背景、任务、动作、工具/协同、结果；指标关联来源。

**5. 沉淀可复用资产** — 更新关键词、简历草稿 bullet、指标清单；可选 JD 映射笔记。

**6. 质量检查与用户确认** — 日期一致、无重复录入、无残缺 STAR、无投递版式要求；用户确认后为优先证据源。

**7. 闭环** — JD 改简历后回写新指标、新表述、被压缩细节。

## 禁止事项

- 编造学校、公司、职级、日期、指标、成果
- 把知识库写成一页投递简历（无四行技能、无 `---` 分隔线等）
- 将知识库全文贴进正式简历
- 在无原始材料时把猜测写入正式条目（应进 `待确认事实`）
