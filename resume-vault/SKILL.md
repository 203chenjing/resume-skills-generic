# 简历素材库

## Goal

维护经用户确认的**经历素材库**（默认 `简历数据库.md`），供 JD 改简历时抽取事实、STAR、指标、关键词与项目层级规则。知识库比投递简历更完整、更原始；**不是**一页 PDF 简历。

默认路径：用户工作区任意约定路径（如 `简历数据库.md`），或用户指定路径。

## 何时必须有知识库

满足**任一**即应先建/更新，再改简历：

| 场景 | 说明 |
|------|------|
| 首次接入 | 尚无 `简历数据库.md`，且后续可能多次改简历 |
| 多次定向改简历 | 同一候选人投多个岗位，需复用 STAR 与指标 |
| 经历结构复杂 | 同一雇主下多条**并列**工作线，或需记录归属/压缩/JD 映射规则 |
| 事实变更 | 新实习/项目/指标，或原始简历已过期 |
| 改简历后压缩 | 被合并/删减的细节应回写知识库 |
| 待核实项 | 日期、职级、指标需集中 `[待确认]` 管理 |
| 用户明确要求 | 建库、更新库、沉淀经历素材 |

## 何时可暂不建库

- 仅改一份简历且不再复用；原始材料完整
- 已有知识库且覆盖本次 JD
- 紧急草稿（交付后提醒补建）

暂不建库时仍不得编造事实；缺指标写 `[待补充：指标]`。

## 与改简历技能分工

| 本 skill | resume-screenpass（过筛选改简历 · ScreenPass Resume） |
|----------|---------------------------------------|
| 沉淀全部可验证事实与 STAR | 按单个 JD 筛选、压缩、排序 |
| 记录层级与 JD 映射规则 | 执行合并/拆条 |
| 指标来源与待确认项 | 投递版只写已确认指标 |

读取顺序：**知识库 → 原始简历 → 用户当次补充**；冲突以用户最新确认为准。JD 改简历后的新指标/新表述/被压缩细节应回写知识库。

## Quick workflow

```
- [ ] 1. 检查是否已有 简历数据库.md，确认本次修订范围
- [ ] 2. 从原始材料导入事实（只搬运，不润色）
- [ ] 3. 按雇主整理并列项目/工作线
- [ ] 4. 对重要工作线补全 STAR
- [ ] 5. 更新关键词、指标清单、待确认区
- [ ] 6. 质量检查并请用户确认
- [ ] 7. 后续改简历后按需回写
```

各步细则见 [reference.md](reference.md)。

## Required inputs

- 原始简历：PDF / Markdown / DOCX 文本 / 用户粘贴或口述
- 可选：本目录 `resume-database-template.md` / `resume-database-l012-template.md`、已有 `简历数据库.md`、实习复盘、项目文档
- 可选：用户指定的库路径与文件名

缺材料时先索取，再写入。

## Output

- 创建或更新 `简历数据库.md`（或用户指定路径）
- **不**在本 skill 中输出投递版简历或 PDF
- 聊天中可简述：新增/更新了哪些区块、哪些仍 `[待确认]`、是否建议下一步按 JD 改简历

## Quality checklist

- [ ] 公司、岗位、项目、日期、指标均有来源或用户确认
- [ ] 雇主下为并列工作线；层级规则写在 `使用规则`，不自造父子关系
- [ ] 主要工作线 STAR 完整；缺指标标 `[待确认]`
- [ ] `指标清单` 可追溯来源；口径一致
- [ ] 无 PDF 一页限制、四行技能、`---` 分隔线等投递版式
- [ ] 用户已确认后，方作为改简历的优先证据源
