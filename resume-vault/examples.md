# 简历知识库 — 匿名结构示例

以下均为**结构范例**，公司名、项目名、数字均为占位，实际编写须替换为候选人真实材料。

## 示例 1：原始层（并列工作线）

```markdown
## 原始简历提取内容

来源：`原始简历.pdf`

### 经历与项目线索

**{公司 A}｜{岗位名称}**
`{起止日期}`

- **{工作线 1}**：{原始职责与动作描述，可含已有指标}
- **{工作线 2}**：{原始描述}
- **{工作线 3}**：{原始描述}

**{公司 B}｜{岗位名称}**
`{起止日期}`

- **{工作线 1}**：{原始描述}
- **{工作线 2}**：{原始描述}
```

要点：同一雇主下多条工作线用 `- **名称**：` 并列，不写父子嵌套。

---

## 示例 2：扩展 STAR 层 + 使用规则

适用于：某雇主下有一条「信息量大、常跨 JD」的深度项目，且与原始层其他工作线**并列**。

```markdown
## {公司}｜{岗位} — {深度项目名称}

### 使用规则

- **项目归属**：{项目名称} 属于 {公司}+{岗位} 实习下的工作点，不是独立实习经历。
- **并列关系**：与原始层中的 `{工作线 A}`、`{工作线 B}` 并列，不得写成总项目统摄子项目。
- **JD 压缩**：
  - 强 {岗位类型 A} JD：可展开 STAR，保留 1 条其他工作线作补充。
  - 非 {岗位类型 A} JD：合并为 1 条「在 {项目名称} 中做了什么」，只保留与 JD 相关的 2–3 类证据。
- **正式简历标题**：实习头只写 `**{公司}**  {岗位}  {日期}`；项目名写在编号条目标题中。

### STAR 1：{主题，如需求调研与机会识别}

- **背景**：{场景与痛点}
- **动作**：{调研对象、方法、产出}
- **结果**：{可量化或定性结果}

### STAR 2：{主题，如方案设计与协同}

- ...

## 可直接改写到简历的版本

- 在 {场景} 中，通过 {方法}，{结果/指标}。
- ...
```

## 示例 3：指标清单

```markdown
## 指标清单

| 指标 | 来源 | 上下文 | 能否写入简历 |
| {核心指标 A 提升 X%} | 原始简历 | {工作线 2} | yes |
| {次要指标 B 下降 Xpp} | 实习复盘 | {工作线 1} | yes |
| {待核实指标} | 口述，未核对 | {项目} | 待确认 |
```

## 示例 4：待确认事实

```markdown
## 待确认事实

- [待确认] {公司} 实习结束日期是否为 {日期}？
- [待确认] 「{指标描述}」是否有报表截图支撑？
- [待确认] 项目对外名称是否可使用「{名称}」？
```

确认后：迁入对应 STAR 或 `指标清单`，并从本区删除。

## 示例 5：可复用关键词

```markdown
## 可复用关键词

- **岗位方向**：{目标岗位 A、目标岗位 B、示例方向…}
- **业务场景**：{核心业务、内容服务、企业内部工具…}
- **通用能力**：{需求调研、路线图、跨团队协同、指标复盘…}
- **工具/方法**：{Python, SQL, A/B 测试, RAG…}
- **量化证据**：{X 类入口、Y 项指标、Z% 提升…}
```
