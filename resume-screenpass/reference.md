# 简历改写（通用版）— 参考细则

本文件供 Agent 在执行 [SKILL.md](SKILL.md) 时按需查阅，不必全文载入上下文。

## 1. 提取事实

- 提取：联系方式、教育、技能、项目、实习/工作、荣誉、日期。
- 合并 `简历数据库.md`（若存在）；库缺失且符合 [resume-vault](../resume-vault/SKILL.md)「必须有」条件时，建议先初始化库。
- PDF 乱码/缺字段 → 请用户提供清晰版或确认不确定项。
- 证件照：至多一张；路径须在工作区内；无图则请用户添加；禁止外链或虚构路径。
- 有 [crop_profile_photo.py](scripts/crop_profile_photo.py) 时，导出前统一尺寸/比例。
- **禁止编造**学校、公司、职级、日期、资质、成果。

## 2. 分析 JD

- 提取：岗位、必备/优先技能、领域、工具、职责、评价关键词。
- 分级：`核心匹配` | `可强化匹配` | `不相关/弱相关`。

## 3. 证据映射

- JD 每条核心要求 ↔ 简历中真实证据。
- 优先保留能证明核心要求的经历；删或压无关内容。

### 项目层级（通用）

| 规则 | 说明 |
|------|------|
| 并列关系 | 同一雇主下多条工作线并列表达；除非原始材料明确，否则不写「总项目统摄子项目」 |
| 按 JD 压缩 | 深度项目与 JD 不完全匹配时，合并为少量编号条，每条一条主线 |
| 禁止机械拆条 | 同一项目（MVP、指标、治理、复盘等）不要拆成多条编号 |
| AI 岗位取舍 | 非强 AI JD：压成流程/指标/协同/运营视角；强 AI JD：可保留方法细节，仍保持并列清晰 |

## 4. STAR 与指标

- 句式：`在[场景/任务]中，使用[方法/工具/动作]，达成[可量化结果/业务影响]。`
- 动词：`搭建`、`优化`、`分析`、`设计`、`落地`、`提升`、`降低`、`自动化`、`沉淀`。
- 工具/关键词贴近结果，须有据；无数据 → `[待补充：指标]`，禁止虚构。
- 条目顺序：`背景/问题 → 方案/协同 → 落地/验证 → 结果/复盘`；避免重复、每条新增证据。

### 数据标黑（量化结果加粗）

- 经历条目中，凡**可量化结果**须用 Markdown 加粗（`**…**`），导出 PDF 后呈黑色加粗，便于 HR 扫读。
- **必须加粗**：百分比、百分点、倍数、条数、人次、评分、时长降幅、实验读数等，例如 `跳出率降低 **2 个百分点**`、`累计沉淀 **5800 条**`、`培训评分 **4.5/5**`。
- **不必加粗**：年份、版本号、课程名、公司/产品专有名、流程描述性文字。
- 一条内多个指标可分别加粗；不要把整句都加粗，只标结果数字及紧挨的单位/量词。
- 缺指标时写 `[待补充：指标]`，不加粗。

### 讲人话（避免中文英文混杂）

- 默认写**通顺中文**，像对人汇报，不要「中文骨架 + 英文词填空」。
- **优先改写为中文**的常见词：

| 避免 | 改为 |
|------|------|
| query | 搜索词 |
| PRD / MVP | 产品需求文档 / 最小可行版本、首期版本 |
| PM | 产品经理 |
| badcase | 问题样本、异常案例 |
| pp | 个百分点 |
| UV lift / CR | 导流用户、转化率（附 **数值**） |
| Case | 案例、工单案例 |
| Agent | 智能体、智能助手 |
| action item | 待办、行动项 |
| A/B / AB | 对照实验、A/B 测试 |
| Eval | 效果评估、评估 |
| Report 模板 | 报告模板 |
| 产运研 | 产品、运营、研发 |
| Web | 网页 |
| debug | 排障、排查 |
| Tool / Skills | 工具 / 技能模块 |
| POC | 概念验证 |
| Prompt | 提示词（技能段可写 Prompt） |
| IQ | 工单（若上下文已说明可保留） |

- **可保留英文**的场景：`相关技能` 中的工具/语言名（Python、SQL、LangChain、Dify）、公司/产品正式英文名、课程英文名、雅思等证书成绩。
- **禁止**同一句里中英文重复表达（如「输出 PRD 产品需求文档」）；**禁止**无必要的中英缩写堆叠（如「梳理 Case 排查 badcase」）。
- 强 AI / 研发岗 JD 可在技能段保留 RAG、LLM 等术语；经历正文仍优先中文表述业务与结果。

### 实习经历编号与项目分层

- 单项目、条目少：公司下用 `1.` `2.` …，每家公司从 1 重新编号。
- **同一实习多个并列项目**（用户偏好或条目较多时）：用项目标题 + 子编号，层次更清晰：

```markdown
**项目一：{项目名}**
{一行简介：仅 1 句，约 25–45 字；Markdown 不加粗}

1）**{职责亮点}：**……结果 **X%**。
2）**{职责亮点}：**……

**项目二：{项目名}**
{一行简介}

1）**{职责亮点}：**……
```

- 子条目用全角 `1）` `2）`，**每个项目内从 1 重新编号**；`**项目二：…**` 另起一组。
- **序号顶格**：`1）` / `1.` 必须从行首第 1 列写起，**行前不得有空格或 Tab**；导出 PDF 时 `1）` 与 `1.` 左缘对齐。
- 项目标题行用 `**项目一：…**` / `**项目：…**`（单项目可用 `**项目：示例项目**`），不写进公司表头。
- **项目简介（硬规则）**：紧挨项目标题下一行；**仅 1 行、1 句**（约 25–45 字）；Markdown 中**不加粗**；导出 PDF 时由脚本渲染为**灰色（`#666666`）斜体**。只点明场景 + 职责边界；**禁止** 2 句及以上长段，**禁止**把调研过程、指标、交付细节写进简介（这些放编号条目），**禁止**堆砌「调研/规格/评审/闭环/提升效率」等空流程词。
- **章节灰底栏（强制样式）**：`## 教育经历` / `## 实习经历` / `## 相关技能` 导出为浅灰底（`#F0F0F0`）+ 左侧深色竖条（`#2C2C2C`）；灰底栏宜偏窄（上下内边距约 `1.5pt`，勿过厚），与定稿参考视觉一致；分隔线 `---` 仅作结构标记，PDF 中不再画粗横线。
- **重点加粗（强制）**：职责亮点标题、可量化结果、关键规模数字必须用 `**…**` 加粗（如 `**需求调研与规格定义：**`、`**20%**`、`**13+**`）；不要整句加粗。
- 职责标题推荐把冒号写进加粗内：`1）**亮点标题：**正文……`（与参考定稿一致）。
- **不限制**每家公司编号条目数量；一页排版由 PDF 页数/留白校验兜底。条目变多时优先 `--preset tight` / `compact` 或压缩措辞，**不要**为凑上限强行合并功能条。
- **禁止**用 `项目一·任务名`、缩进简介、`1）` 与 `1.` 在同一实习段混用编号风格。
- **禁止**为凑页数把简介写成长段；偏空时优先加长编号条目正文（真实事实），再考虑 preset。

### 导出脚本识别的 Markdown 语法

本 skill 目录下 `scripts/markdown_resume_to_pdf.py`（与包内 `shared/scripts/` 同步）支持：

| 写法 | 渲染 |
|------|------|
| `**项目一：名称**` + 下一行简介 | 加粗项目标题 + **灰色斜体**简介段 |
| `项目一：名称：简介`（单行，无加粗） | 标题加粗、简介灰色斜体（少用） |
| `1）**任务：**正文` | 顶格序号 + 任务条（`p.project-task`；任务名加粗） |
| `1. **任务**：正文` | 有序列表（技能段、单项目实习） |

校验规则：`check_resume_skill.py` 会检查各项目内 `1）` 是否从 1 递增；**不**因条目数量 fail；**不**检查加粗与中文混排（须人工审阅）。

## 5. Markdown 版式规则

默认结构见 [resume-template.md](resume-template.md)。

### 章节与分隔

- 顺序：姓名联系方式 → 教育 → 实习经历 → 相关技能。
- `## 实习经历`、`## 相关技能` 前各一行 `---`，与标题之间**无空行**；不用 `***` / `___`。
- 禁止 `求职优势`、`求职摘要`、`个人总结` 等独立块。
- 正文不写证据映射、分析备注等内部内容。

### 教育经历

- 每校两行：`**学校**  学历，时间` + 教育事实（专业、成绩、课程、荣誉等）。
- 不写软技能或岗位匹配话术。

### 实习经历

- 表头一行：`**公司**  岗位名称  时间`（导出为三列对齐，勿用手动全角空格或 `| 表头 |`）。
- 项目名、JD 词放在项目标题或编号条目中，不写进公司表头。
- 编号方式见上文「实习经历编号与项目分层」；条目数量不设硬上限，以一页可读为准。

### 相关技能（固定 4 行）

单行有序列表，标签加粗、不可换行续写：

1. `**工作技能**：` 产品/运营/协作  
2. `**数据技能**：` 数据工具与分析  
3. `**AI技能**：` AI/LLM/Agent 等  
4. `**语言能力**：` 成绩与英文办公场景  

**AI技能 须泛化**：写工具、方法论与岗位适配（如「理解相关项目在立项、验收、风险治理中的管理要点」），**禁止**写具体实习项目模块细节（如「理解某业务模块触发规则」）。项目细节放在实习经历，技能段只沉淀可迁移能力。

### 证件照

- `![个人照片](相对路径)`，一张；导出前确认存在；PDF 中不遮挡正文。

### 篇幅与疏密

- 目标：一页 A4，**内容充实**、不溢出；视觉样式对齐定稿参考（灰底左竖条分区、姓名下划线、项目简介左灰条斜体）。以后全部中文一页简历默认此样式。**相关技能**四行与实习经历编号条目一致，**不要**技能行间灰色横线。
- 项目简介保持 **仅 1 行 / 1 句**；充实靠编号条目（每条写清事实与指标），不要把流程词或长背景堆进简介。
- 偏空：先加长编号条目正文，再考虑 `fill` / `compact` preset；禁止只靠增大行距/留白交差。
- 偏满：先压教育次要课程、合并弱条目、收紧技能四行，再考虑 `tight` preset。

### 行宽与信息密度（强制）

PDF 正文为两端对齐后，**禁止「每一行只写一点点」的空疏版面**。写 Markdown 时就要按行宽饱满度自检，不要等导出后再靠拉行距补救。

| 规则 | 要求 |
|------|------|
| 条目长度 | 单条编号经历宜约 **80–140 汉字**（不含标题加粗部分亦可计入整体观感）；至少 **2–4 个完整分句**，覆盖场景/动作/协同或规则/结果，避免「半句就换条」 |
| 折行观感 | 导出后扫一眼：折行后的**末行不要只剩 4–10 个字孤零零占一行**；若多条都是「前两行满、末行只剩几个字」，优先**补真实细节**把末行填满，或微调分句使折行更均衡 |
| 技能四行 | `相关技能` 每一行都要写到**接近行末**（工具 + 能做什么 + 岗位可迁移场景）；禁止「标签后只跟两三个词」 |
| 禁止做法 | 为凑短而砍掉动作/结果只留口号；标题很长、正文极短；用空流程词（「闭环/赋能/落地」）灌字却不增事实 |
| 允许做法 | 在事实边界内补触发规则、协同对象、验收口径、指标单位；超页时先压缩冗余措辞，再 `tight`，**不要**先砍成半行短句 |

审阅口诀：**宁可一条写满两行半，也不要三条各半行。**

### PDF 视觉样式（导出脚本）

| 元素 | Markdown | PDF 表现 |
|------|----------|----------|
| 章节标题 `## 教育/实习/技能` | 普通二级标题 | **浅灰底栏 `#F0F0F0` + 左侧深色竖条**（上下内边距约 `1.5pt`，偏窄） |
| 项目标题 `**项目一：…**` | 加粗 | 黑色加粗 |
| 项目简介（标题下一行） | 普通正文、不加粗；**1 句点到为止** | **灰色 `#666` + 斜体** |
| 职责亮点 `**标题：**` | 加粗 | 黑色加粗 |
| 量化结果 `**20%**` 等 | 加粗 | 黑色加粗 |
| 正文其余 | 普通 | 黑色常规字重 |
| `---` 分隔 | 结构标记 | 不渲染粗横线（章节灰底栏已区分区块） |

## 6. 导出与一页循环

### 命令

```bash
python scripts/check_resume_skill.py input.md --markdown-only
python scripts/markdown_resume_to_pdf.py input.md
python scripts/check_resume_skill.py input.md
```

- 默认省略 `-o`，推断 `公司+姓名+岗位.pdf`。
- preset：`standard` | `tight`（内容已紧仍略超页）| `fill`（1 页但底部过空）。

### 循环

`写 Markdown → 人工内容审阅 → 格式预检 → 导出 PDF → 读结果 → 调内容或 preset → 重复`

### 通过条件

- `Page check: 1 page.`
- `Skill check: passed.`
- 否则为草稿。

### 故障处理

| 现象 | 处理 |
|------|------|
| PDF ≥ 2 页 | 先压措辞（教育次要信息、技能 4 行、条目正文收紧），再 `tight` / `compact`；勿为页数强行合并功能条 |
| 1 页但留白 >20mm | 先补真实 JD 经历，再 `fill` |
| 照片缺/裁切/重叠 | 裁剪脚本或改路径后重导 |
| 版式检查失败 | 按报错改 Markdown |
| 仅需 Markdown | 可只交 MD；用户要 PDF 时不得以 MD 代替终稿 |

### 脚本职责边界

- `check_resume_skill.py`：分隔线、技能行、文件名、照片、页数、留白、有序列表等。
- **不**验证：真实性、JD 匹配、证据质量、项目层级逻辑。

终稿前须完成**人工内容审阅**；流程要求时须**用户确认**事实/指标/敏感表述。

## Markdown 转 PDF 版式

| 项 | 值 |
|----|-----|
| 页面 | A4 |
| 页边距 | 上 2.0cm，下约 0.8cm，左右 2.0cm |
| 字号 | 姓名/章节加粗；正文约 9.5pt |
| 行高 | 1.3 |
| 表头行 | 略大于正文（约 10.5–11pt 加粗），三列固定 |
| 联系方式 | 居中 |
| 正文 | 两端对齐，勿手动断行凑对齐 |

**末行距页底**：最佳 6–10mm，可接受 3–15mm；>20mm 视为过空。
